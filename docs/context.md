## 1. 프로젝트 개요

* **장르**: 실시간 턴제 카드 배틀로얄 웹 게임 (원작 유즈맵 이식)
* **인원**: 원작(SC1)은 2~4인. 웹 버전은 2~6인까지 확장 검토 (7장)
* **핵심 재미**: 누적 데미지 넘기기, 밈 카드의 어이없는 효과, 저주·역전 카드로 인한 난장판
* **1단계 운영**: 초대 코드로만 들어오는 비공개 방
* **장기**: 카드팩과 규칙 차별화 후 공개/상업 버전 가능성 검토 (5.2)

## 2. 원작 조사 요약

### 2.1 원작 계보

| 버전 | 제작 | 요약 |
|---|---|---|
| EUD 랜덤카드배틀 (SC1) | GRAYD | 원조. 2~4인, 한국 인터넷 밈 카드. 공식 패치는 1.14에서 중단, 이후 비공식 1.17.1 / 1.19.1 존재. 약 3년간 배틀넷 인기 맵이었으나 리마스터에서 EUD·이미지 지원이 막혀 사실상 플레이 곤란 |
| 랜덤카드배틀 (SC2) | DragonMod (원작자 아님) | 원작 기반. 기본 규칙 거의 동일, 손패 5→6장, 단축키로 빠른 제출, 일부 카드 일러스트·이름 교체 |
| 병맛 랜덤 카드 배틀 (SC2) | — | 카드 대거 추가, 파워 인플레, 필드 카드·고문 카드·종족 태그 등 시스템 확장 |
| 보드게임 버전 | 마츠 | **원작자 GRAYD의 허락을 받고 제작**. 오리지널판과 장착 카드가 추가된 리마스터판 존재 |

### 2.2 기본 규칙 (SC1 기준)

* 시작 체력 200, 0이 되면 패배. 체력은 200을 넘어 회복 가능 (상한 존재)
* 자기 차례엔 반드시 카드 1장을 내야 하며, 못 내거나 내기 싫으면 카드 1장을 버린다
* 필드에는 두 값이 있다
  * **현재 공격력**: 직전에 나온 공격 카드의 공격력
  * **누적 데미지**: 지금까지 쌓인 공격력 합
* 현재 공격력이 없거나, 내가 낸 공격 카드가 현재 공격력보다 **높으면** → 피해 없이 누적 데미지에 더해 다음 차례로 넘어감
* 현재 공격력보다 **낮은** 공격 카드를 내거나, 누적 데미지와 무관한 카드를 내면 → 쌓인 누적 데미지를 **전부 내가 받음**
* 누적 데미지·저주 정산은 **자기 턴이 끝날 때** 일어남 → 죽을 상황에서도 카드 효과로 역전 가능
* 손패 5장 기본, 턴 제한 시간 있음, 턴 순서는 고정(단, 역방향·스킵 카드 존재)

### 2.3 SC2 버전의 규칙 차이

* 시작 체력(350~1000)과 제한 시간을 방 설정으로 선택
* 현재 공격력보다 **낮거나 같은** 카드를 내면 → (누적 − 현재 공격력)만큼만 피해
* 반동 데미지 삭제
* 제한 시간 초과 시 무작위 카드가 버려짐
* **스페셜 카드**: 여러 제약을 무시하고 항상 낼 수 있음. 일부는 "이후 더 높은 공격 카드만 낼 수 있게" 락을 검
* 체력이 일정 이하일 때 1회 쓸 수 있는 역전 드로우 스킬
* 카드에 속성·종족 태그가 붙고, 태그를 참조하는 카드가 많음
* 직접 덱을 짜는 커스텀 모드, 특정 시점 카드만 쓰는 클래식 모드

### 2.4 카드 분류 체계

| 대분류 | 하위 분류 (SC1 기준) | 메카닉 요약 |
|---|---|---|
| 공격 | 일반, 속성(화염·전기), 회복형, 증폭형, 무효형, 기타형 | 공격력으로 누적 데미지를 올리며 넘김. 조건부 공격력 증가, 필드 락, 누적 초기화, 저주 해제 등이 붙음 |
| 보조 | 데미지 감소, 데미지 전달, 방어형 | 누적 데미지를 줄이거나 다음/이전/지정/무작위 대상에게 넘김. 배수로 넘기기, 공격력↔누적 교환 등 |
| 이득 | 회복, 카드, 공격, 저주 | 누적과 무관한 이득. 회복, 손패 한도 증가, 손패 교체, 직접 피해, 추가 제출, 저주 해제·반사 |
| 저주 | — | 대상에게 거는 지속 디버프. 턴마다 체력 감소·흡수, 특정 종류 카드 봉인, 손패 공개, 손패 한도 감소, 턴 시간 단축, 대상 지정 강제 등 |
| 기타 | — | 전원 손패 교체, 체력 재설정·교환·평준화, 확률 카드, 순서 역전·스킵, 무승부 카운트다운 등 |
| 필드 / 고문 (SC2 확장) | — | 필드 지속 효과 카드, 상대 손패에 떠넘기는 방해 카드 |

### 2.5 엔진이 반드시 지원해야 할 특수 규칙

* **속성 태그**: SC1은 화염·전기 2종. 특정 무효 카드·확률 폭탄과 상호작용 → 태그 시스템으로 일반화 (SC2 종족 태그까지 수용)
* **필드 락**: 특정 카드가 필드에 있는 동안 공격 카드 전부 / 일정 공격력 이상 / 보조 / 회복 / 이득 / 기타 카드 제출 금지
* **저주 규칙**: 1인당 1개, 새 저주가 기존 저주를 덮어씀, 자연 해제 없음(해제 카드 필요), 시전자가 탈락하면 해제(SC1; SC2는 유지), 대상 턴 종료 시 발동
* **지속 효과**: N턴 지속(보호막, 지속 회복 등), 다음 턴 버프
* **무조건 제출 가능 플래그**: 필드 락·저주를 무시
* **제출 조건**: 체력 N 이하일 때만, 누적 N 이상일 때만, 누적이 없을 때만 등
* **추가 제출 체인**: "카드를 한 장 더 낼 수 있음" (공격력 합산, 배수 적용 등)
* **대상 지정**: 원하는 플레이어 지정, 지정 불가 상태(보호막), 대상 강제 고정(저주)
* **확률**: 공격력 범위 랜덤, 확률 발동, 시한폭탄(매 턴 확률 폭발, 정산 맨 마지막에 판정)
* **정보 공개**: 특정 대상의 손패를 전원에게 공개
* **손패 조작**: 한도 증감, 전원/대상 교체, 손패 교환, 특정 카드로 전부 교체, 필드에서 카드 회수
* **게임 흐름 조작**: 순서 역전, 다음 차례 스킵, 다음 플레이어 행동 불가, 무승부 카운트다운

## 3. 게임 엔진 설계

### 3.1 상태 모델

```
Game
  id, ruleMode(SC1 | SC2), packId, rngSeed
  players[]          // 좌석 순서
  direction          // +1 / -1
  currentTurn        // 좌석 인덱스
  currentAttack      // 현재 공격력
  accumulatedDamage  // 누적 데미지
  field[]            // 필드 카드 (ownerId, expiresAtTurn)
  pendingPlays       // 추가 제출 체인 상태
  drawTimer          // 무승부 카운트다운 (nullable)
  turnDeadline       // 턴 마감 시각

Player
  id, seat, hp, hpCap
  hand[], handLimit
  curse              // 0..1 (curseCardId, casterId)
  statuses[]         // 지속 효과 (type, remainingTurns, params)
  flags              // 스킵 예약, 행동 불가, 대상 지정 불가 등
  eliminated
```

### 3.2 턴 처리 파이프라인

1. **턴 시작**: 스킵·행동 불가 확인, 턴 마감 시각 설정
2. **제출 검증**: 손패 소유 → 무조건 제출 플래그 → 필드 락 → 저주 락 → 카드별 제출 조건
3. **효과 적용**: 카드 효과 실행 (추가 제출 체인이 있으면 2~3 반복)
4. **누적 판정**: 공격 카드 & 현재 공격력보다 **같거나 높음** → 누적 += 공격력, 현재 공격력 갱신 / 낮은 공격 카드 → 누적 데미지 수령 후 그 카드로 새 체인 시작 / 그 외 → 누적 데미지 수령 예약 (보조 카드가 처리한 경우 제외)
   * SC2 모드: 같거나 낮으면 (누적 − 현재 공격력)만 수령
5. **턴 종료 정산**: 누적 피해 → 저주 효과 → 지속 효과 → 시한폭탄류 확률 판정
6. **탈락·종료 판정**: 체력 0 탈락, 시전자 탈락 시 저주 해제(SC1), 1인 남으면 승리, 무승부 카운트다운
7. **드로우**: 손패 한도까지 보충
8. **다음 차례**: 방향·스킵 반영

> 정산 순서의 세부(같은 타이밍 효과끼리의 우선순위)는 원작 플레이 영상으로 확인 후 확정 (7장)

### 3.3 카드 데이터 모델 (DB)

```
card_pack   (id, name, visibility[PRIVATE|PUBLIC], rule_mode, version)
card        (id, pack_id, name, category, subcategory,
             attack, attack_min, attack_max,     -- 랜덤 공격력
             tags[],                             -- 속성·종족
             always_playable, special_lock,
             play_conditions JSONB,
             effects JSONB,                      -- 이펙트 프리미티브 목록
             description, flavor, image_key, weight)  -- weight = 드로우 확률
```

**이펙트 프리미티브 (effects JSON의 type)** — 원작 카드는 이 조합으로 표현

| 그룹 | 프리미티브 |
|---|---|
| 누적 | MODIFY_ACCUMULATED(op, value), RESET_ACCUMULATED, TRANSFER_ACCUMULATED(target, multiplier, immediate), SWAP_ATTACK_AND_ACCUMULATED, ABSORB_ACCUMULATED_AS_HP |
| 체력 | DAMAGE(target, amount), HEAL(target, amount), DRAIN, SET_HP, SWAP_HP, EQUALIZE_HP, HALVE_HP, SET_HP_CAP |
| 저주/상태 | APPLY_CURSE(curseDef), REMOVE_CURSE(scope), REFLECT_CURSE, APPLY_STATUS(type, turns), UNTARGETABLE(turns), DISPEL_STATUSES |
| 필드 | FIELD_LOCK(filter), CONDITIONAL_ATTACK(ifFieldHas, bonus) |
| 제출 | EXTRA_PLAY(filter, modifiers), PLAY_ALL(filter) |
| 손패 | DRAW, REPLACE_HAND(scope), SWAP_HAND, HAND_LIMIT(op, value), REVEAL_HAND, RETRIEVE_FROM_FIELD, GIVE_CARDS |
| 흐름 | SKIP_NEXT, REVERSE_ORDER, LOCK_NEXT_PLAYER, SET_TURN_TIME, START_DRAW_COUNTDOWN |
| 확률 | RANDOM_CHOICE(table), CHANCE(p, then, else), TIME_BOMB(p, damage, modifiersByTag) |

* 효과 실행: Java Strategy 패턴 (프리미티브 타입별 핸들러)
* 제출 가능 판정: 카드 JSON의 조건 목록(conditions)을 Java에서 평가. 외부 룰 엔진(ZEN)은 보류
* 카드 데이터는 서버 시작 시 메모리에 캐시

### 3.4 카드팩 교체 구조

* 방 생성 시 packId 선택
* **PRIVATE 팩(원작 카드)은 초대 코드 방에서만 선택 가능**
* 엔진 코드는 팩 내용을 모름 → 팩만 바꾸면 공개 버전

### 3.5 무작위성

* 원작은 확률 카드가 많으므로 서버 시드 RNG 사용
* 시드와 입력 로그를 남겨 버그 재현·리플레이에 활용

## 4. 시스템 아키텍처 및 기술 스택

| 영역 | 선택 | 비고 |
|---|---|---|
| 백엔드 | Spring Boot 4.1, Java 21 | 가상 스레드 활성화 (`spring.threads.virtual.enabled=true`). Jackson 3(tools.jackson) 사용 |
| 통신 | WebSocket + STOMP | `@MessageMapping`, `SimpMessagingTemplate` |
| 다중 서버 브로드캐스트 | 인스턴스별 SimpleBroker + Redis Pub/Sub | `RedisMessageListenerContainer`로 받은 이벤트를 로컬 세션에 재전송 (Spring STOMP broker relay는 Redis 불가) |
| 게임 상태 | Redis (방 단위) | 서버 무상태. 동시 입력은 버전 필드 + Lua 스크립트(CAS) |
| 턴 타이머 | Redis ZSET 마감 큐 | 마감 시각을 ZSET에 넣고 워커가 폴링 → 서버가 죽어도 타이머 유지. 초과 시 무작위 버리기(원작 동작) |
| 카드 DB | PostgreSQL | **Phase 1부터 사용** (카드팩이 DB에 있으므로) |
| 룰 엔진 | Java Strategy + 조건 JSON | 외부 룰 엔진(GoRules ZEN)은 **보류**. 효과는 프리미티브 핸들러, 제출 조건은 카드 JSON의 조건 목록으로 판정 |
| 숨김 정보 | 서버 전용 | 손패는 사용자 전용 큐(`/user/queue/...`)로만 전송. 손패 공개 저주 시에만 전체 전송 |
| 안티 치트 | 100% 서버 권위 | 클라이언트는 입력만 전송 |
| 반응성 | 낙관적 UI | 카드 먼저 내려놓는 연출 → 서버 거절 시 되돌림 |
| 동기화 | 스냅샷 + 델타 | 단선 시 지수적 백오프(+지터) 재접속 |
| 매치메이킹 | Redis ZSET | 공개 버전(Phase 4)에서만 |

## 5. 제약 사항 & 배포 정책

### 5.1 비공개 운영 규칙

* **원작 카드 데이터는 private 레포 또는 서버 DB에만.** 공개 레포에는 절대 커밋하지 않음 (시드 SQL/JSON은 `.gitignore`, 별도 private 저장소)
* 공개 레포에는 엔진 코드와 오리지널 샘플 팩만
* 서버 접근은 초대 코드 + 로그인으로 제한
* **사용 금지**: 원작 카드 이미지, 스타크래프트 리소스(유닛·사운드·UI), 원작 맵의 BGM(외부 음원) → 텍스트 카드로 구현
* **원작자 GRAYD에게 연락해 허락 요청 권장** (보드게임 버전이 허락을 받고 제작된 선례 있음)

### 5.2 공개/상업 전환 시

* **카드 데이터 교체만으로는 부족할 수 있음.** 개별 규칙은 아이디어라 보호되지 않지만, 규칙을 선택·조합한 결과는 저작물로 보호될 수 있음 (대법원 2019. 6. 27. 선고 2017다212095). 누적 데미지 + 현재 공격력 비교 + 카드 분류 체계 + 저주 규칙까지 원작과 같으면 문제될 수 있음
* 선택지: ① 원작자 허락 ② 규칙 차별화 (v2의 과부하 코어·임계점·유령 등 재활용) ③ 둘 다
* 공개 팩 밈 가이드

| 구분 | 판단 |
|---|---|
| 상황 밈, 흔한 인터넷 표현, 패러디 포맷 | 사용 가능 |
| 실존 인물·방송인·스트리머의 얼굴, 이름, 고유 유행어 | 사용 금지 (초상권, 부정경쟁방지법상 유명인 표지 무단 사용) |
| 애니·드라마·영화·타 게임의 캐릭터, 장면, 대사 | 사용 금지 (저작권) |
| 특정 집단·장애·성적 지향을 비하하는 밈 | 사용 금지 |

* 원작 카드 상당수가 위 금지 항목에 걸리므로, 공개 팩은 사실상 새로 만들어야 함
* 출시 전 게임 IP 분야 법률 자문 1회

## 6. 단계별 개발 마일스톤

* **Phase 1 (MVP — 코어 루프)**
  Spring Boot + STOMP + Redis, 초대 코드 방, 턴 루프(제출/버리기, 현재 공격력·누적 판정, 턴 종료 정산, 드로우), 턴 타이머, PostgreSQL 카드팩. 카드는 공격 + 데미지 감소·전달만 (프리미티브 최소 세트)
* **Phase 2 (원작 카드 전체)**
  저주, 필드 락, 지속 효과, 추가 제출 체인, 태그, 확률, 순서 조작, 손패 조작, 무승부 카운트다운, 룰 모드(SC1/SC2)
* **Phase 3 (안정성)**
  재접속, 스냅샷/델타, 낙관적 UI, 시드 기반 리플레이 로그
* **Phase 4 (공개 준비)**
  오리지널 카드팩, 규칙 차별화 또는 원작자 허락, 매치메이킹, 부하 테스트, BM 검토
